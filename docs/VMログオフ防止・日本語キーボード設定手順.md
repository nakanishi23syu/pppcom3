# VM環境構築 ― すぐログオフ(再サインイン要求)される問題／日本語キーボード配列にならない問題の直し方（GUI版）

> 会社のPC環境（Windows ServerのVM）を構築する際によく遭遇する2つの問題への対処法。
> `dicom-pacs-vm`（Windows Server 2025）で実際に設定・再起動まで行い、動作確認済みの内容を、
> **GUI操作だけで**行えるように書き換えたものです。コマンドプロンプト/PowerShellでのコマンド
> 入力は一切使わず、すべてマウスクリックとダイアログ操作で完結します
> （ツールを開くためだけに「ファイル名を指定して実行」を使う箇所はありますが、
> 設定変更そのものはGUI上で行います）。

---

## 1. 起動後しばらくするとサインイン画面に戻ってしまう問題

### 1-1. まず切り分ける：ローカル設定が原因か、ドメインのグループポリシーが原因か

社内の会社PCはActive Directoryドメインに参加していることが多く、その場合は
「ローカルの設定をいくら変えても、ドメイン側のグループポリシー（GPO）が定期的に
上書きしてくる」ということが起こる。これが原因の場合、ローカル設定の変更だけでは直らない。

**ドメイン参加しているか確認する:**

1. スタートボタンを右クリック →「システム」を開く。
2. 「関連リンク」または「デバイス仕様」欄に「ワークグループ」ではなく
   「ドメイン」と表示されていればドメイン参加している。

**実際に適用されているグループポリシーをGUIで確認する（重要）:**

1. `Win + R`キーで「ファイル名を指定して実行」を開き、`rsop.msc`と入力してEnter。
   （これは「現在このマシンに実際に効いているポリシー」を表示する専用のGUIツール。
   ローカル設定だけでなく、ドメインから配布されたポリシーも含めて一覧できる。）
2. ツリーの左側で「コンピューターの構成」→「Windowsの設定」→「セキュリティの設定」→
   「ローカルポリシー」→「セキュリティオプション」を開く。
3. 一覧の中から以下の項目を探し、値の列を確認する。
   - **「インタラクティブ ログオン: マシンの非アクティブ制限」**
     （英語表記なら "Interactive logon: Machine inactivity limit"）
4. さらに「コンピューターの構成」→「管理用テンプレート」→「コントロールパネル」→
   「個人設定」も確認し、画面セーバーに関するポリシーが設定されていないか見る。

これらの項目の右側に「未定義」ではなく**具体的な秒数（例: 900秒）**や「有効」が
表示されている場合、それがドメイン側から強制されている証拠。この場合はローカルでの
変更が意味をなさないので、社内の情報システム担当・ドメイン管理者に「このマシン
（またはOU）だけこのポリシーを緩めてほしい」と依頼する必要がある。以下の1-2〜1-3の
手順は、あくまで**ローカル設定が原因の場合**、またはドメイン非参加のスタンドアロン環境
（今回検証したVM等）向けの対処。

### 1-2. ローカル設定をGUIで確認・修正する

#### a. ディスプレイの電源オフ設定を「なし」にする

1. スタートメニューで「電源とスリープの設定」と検索して開く
   （またはコントロールパネル →「電源オプション」→ 左側の「ディスプレイの電源を切る
   タイミングの変更」）。
2. 「画面」欄の「次の時間が経過後、画面の電源を切る」を**「なし」**に変更する。
3. 「スリープ」欄の「次の時間が経過後、PCをスリープ状態にする」も**「なし」**に
   変更しておく（VMware等のコンソール接続では、物理ディスプレイの節電もスリープも
   意味がないため）。

#### b. 画面セーバーによる自動ロックを無効化する

1. スタートメニューで「スクリーンセーバーの変更」と検索して開く
   （またはデスクトップを右クリック →「個人用設定」→「ロック画面」→
   「スクリーン セーバー設定」）。
2. 表示された「スクリーンセーバーの設定」ダイアログで、上部のドロップダウンを
   **「(なし)」**に変更する。
3. その下にある**「再開時にログオン画面に戻る」チェックボックスを外す**
   （このチェックが入っていると、スクリーンセーバーから復帰する際に強制的に
   サインイン画面に戻される。これが「すぐログオフしちゃう」の直接的な原因になっている
   ことが多い）。
4. 「OK」で閉じる。

#### c. 変更が反映されたか確認する

1-1と同じ`rsop.msc`、または単純にもう一度「電源とスリープの設定」「スクリーンセーバーの
設定」画面を開き直し、上記の変更内容がそのまま表示されていればOK。`dicom-pacs-vm`では
実際にこの状態にした上でVMを再起動し、自動サインインでコンソール画面が問題なく復帰する
ことを確認済み。

### 1-3. （任意・要検討）自動サインインの設定

そもそも起動のたびにサインインし直すこと自体が面倒な場合、Windowsの「自動サインイン」
機能を使うこともできる。

1. `Win + R`で「ファイル名を指定して実行」を開き、`netplwiz`と入力してEnter
   （ユーザーアカウントの設定画面が開く）。
2. ユーザー一覧から自動サインインさせたいアカウントを選択する。
3. 一覧の上にある**「ユーザーがこのコンピューターを使うには、ユーザー名とパスワードを
   入力する必要がある」チェックボックスを外す**。
4. 「OK」を押すと、ユーザー名とパスワードの入力を求めるダイアログが出るので入力して
   確定する（これで裏側の自動サインイン設定が行われる）。

**注意（重要）:** この方法もパスワードを保存する点は変わらない（内部的にはレジストリに
保存される）。個人検証用VMなら実用上問題ないことが多いが、会社の管理下にあるマシン・
ドメインアカウントでこれを行うのはセキュリティポリシー上NGな場合が多い。会社PCで導入する
前に、必ず情報システム部門に可否を確認すること。`dicom-pacs-vm`ではローカルアカウントに
対してこの設定が既に入っており、1-2の設定と組み合わせて「起動後、操作せず放置しても
サインイン画面に戻らない」状態を実現している。

## 2. 日本語キーボード配列にならない問題

### 2-1. 原因

言語設定（入力方式・IME）が日本語になっていても、**キーボードの「物理的なハードウェア
ドライバー」が英語配列（101/104キー）用のまま**になっていることがある。これはVMware等の
仮想マシンで特によく起きる。IME側は日本語で正常動作しているように見えるため気づきにくいが、
`@`・`"`・`:`・`[`・`]`等の記号キーの物理位置がJIS配列と対応しておらず、押した場所と
入力される記号がずれる。

**確認方法:**

1. `Win + X`（またはスタートボタンを右クリック）→「デバイス マネージャー」を開く。
2. 「キーボード」の項目を展開する。
3. 表示されているデバイス名を確認する。

**`Standard PS/2 Keyboard`（＝英語101/104キー用の汎用ドライバー）**になっていれば、
これが原因である可能性が高い。`dicom-pacs-vm`でも実際にこの状態だった。日本語106/109
キーボードとして正しく認識されていれば、通常は`Japanese PS/2 Keyboard (106/109 Key)`の
ような名前になる。

### 2-2. 修正方法（デバイスマネージャーからドライバーを選び直す）

1. デバイスマネージャーの「キーボード」配下にある`Standard PS/2 Keyboard`を右クリック
   →「ドライバーの更新」を選ぶ。
2. 「コンピューターを参照してドライバーを検索」を選ぶ。
3. 「コンピューター上のデバイス ドライバーの一覧から選択します」を選ぶ。
4. 「互換性のあるハードウェアを表示」のチェックが入っていると候補に出てこないことが
   あるので、**チェックを外す**。
5. 「製造元」の一覧から**「Standard keyboards」**を選ぶ。
6. 右側の「モデル」一覧から**「Japanese PS/2 Keyboard (106/109 Key)」**を選び、
   「次へ」をクリックする。
7. 「このドライバーをインストールしますか」という警告が出たら「はい」を選ぶ。
8. インストール完了後、**「今すぐ再起動」を選んで再起動する**
   （キーボードドライバーはOS起動時にしか読み込まれないため、再起動しないと反映されない。
   これはWindows標準のドライバーに含まれる正規の日本語キーボード設定であり、内部的には
   コマンドで直接設定した場合と同じ`OverrideKeyboardIdentifier=PCAT_106KEY`という設定が
   Windows側で自動的に書き込まれる。`dicom-pacs-vm`ではこの内部設定値が再起動後も正しく
   保持されることを確認済み）。

### 2-3. 動作確認

再起動後、以下の記号を実際に打ち、キートップに印字された記号どおりに入力されるか
目視で確認する（これはリモートやコマンドでは確認できず、実際にキーを押して確認する
しかない箇所）。

| キー（JIS配列の位置） | 期待される入力結果 |
| --- | --- |
| `@`キー（Pの右） | `@`（Shiftなし）／`` ` ``（Shiftあり） |
| `:`キー（Lの右） | `:`（Shiftなし）／`*`（Shiftあり） |
| `]`キーの右にある`\`（Enterの左上あたり） | `]`（Shiftなし）／`}`（Shiftあり） |
| 半角/全角キー | IMEのオン/オフが切り替わる |
| 無変換・変換キー（スペースキー両脇） | それぞれ無変換/変換動作をする |

これらが期待通りにならない場合は、2-2の手順4「モデル」一覧の中に他の日本語向け候補
（`Japanese PS/2 Keyboard (106/109 Key Ctrl + Eisuu)`等）がないか確認し、そちらを
試してみる（環境によって適切なモデルが異なることがある）。

## 3. トラブルシュート

### 1章の設定をしても再起動のたびにサインイン画面に戻る（会社PCの場合）

- 1-1の`rsop.msc`確認をやり直す。ドメイン管理者に`gpupdate /force`を依頼した直後に
  再現するなら、ほぼ確実にドメイン側のポリシーが原因。
- リモートデスクトップ経由でアクセスしている場合、「ログオフ」ではなく
  「セッションの切断→再接続時にサインインし直しているだけ」の可能性もある。この場合は
  `gpedit.msc`（ローカルグループポリシーエディター）の「コンピューターの構成」→
  「管理用テンプレート」→「Windowsコンポーネント」→「リモートデスクトップサービス」→
  「リモートデスクトップセッションホスト」→「セッションの時間制限」の項目を確認する。

### 2章の設定をしても記号がずれたまま

- デバイスマネージャー上の表示名が更新されていなくても、再起動していれば内部的な変換
  処理自体は変わっているはず。表示名の見た目より2-3の実打鍵確認を優先する。
- VMware Workstation側のキーボード設定（ホストOSのキーボードをそのままパススルーする
  設定になっているか）も確認する。ホスト側がUSキーボードとして扱われていると、
  ゲスト側だけ直しても正しく入らないことがある。
- それでも直らない場合は、デバイスマネージャーで一旦「ドライバーのアンインストール」を
  行い（デバイスの削除ではなくドライバーのみ）、PCを再起動して自動再検出させたうえで、
  改めて2-2の手順をやり直す。
- 別の方法として、設定アプリの「時刻と言語」→「言語と地域」→「日本語」の「…」メニュー
  →「言語のオプション」→「キーボード」欄の「レイアウトの変更」からも、入力方式側の
  レイアウトを明示的に選び直せる（ただしこちらはIME側の設定で、2-2のハードウェア
  ドライバーの設定とは別レイヤーのため、両方の状態を合わせて確認するとよい）。
